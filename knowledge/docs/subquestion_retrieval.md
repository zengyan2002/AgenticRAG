# 按子问题组织复杂查询检索

进入 Agentic 流程且计划包含多个子问题时，使用分组检索。普通查询及只有一个子问题的计划继续使用原链路。

## 执行过程

1. Planner 的 `sub_questions` 定义答案必须覆盖的要求，`retrieval_tasks` 用固定的 `subquestion_index` 绑定检索表达和工具。每题最多两条表达。缺失任务按对应子问题补齐，重复任务合并，越界任务忽略；索引不因子问题去重而移动。
2. 各召回分支内，仅融合同一题的查询变体。之后 RRF 节点仅在该题内融合 vector、BM25、HyDE；向量分支仍在 Milvus 内融合 Dense/Sparse。HyDE 每题至多生成一份假设文档。分支外层仍由 LangGraph 并行执行，每个分支内部顺序请求。
3. Reranker 将各题的 `(子问题, 候选正文)` 配对一起送入模型，按 `AGENT_RERANK_BATCH_SIZE` 分批。分数仅在组内排序，每题最多保留 `AGENT_SUBQUESTION_TOP_K` 条。正常评分低于已有相关性阈值的结果不凑数；模型失败则各组回退 RRF 顺序。
4. 跨题轮流取证、按 Chunk ID 去重。`retrieved_for_subquestions` 表示候选归属，`subquestion_scores` 保留组内分数；这些字段不是“证据已经充分”的证明。不再跨题做 RRF、全局 Rerank 或按全局分数 TopK 截断。旧的全局排序分歧仲裁在此路径跳过。
5. Evaluator 按固定索引验收覆盖，返回 `missing_subquestion_indices` 和 `followup_tasks`。无候选、越界的已覆盖声明无效。缺失项存在时，即使模型给出 `next_action=answer` 也会改为补检索。
6. Replan 只执行缺失且依赖已满足的子问题；已完成组保留。缺失组的新旧候选一起重新评分。每轮新证据按 `(子问题索引, Chunk ID)` 判断，避免“同一 Chunk 新回答另一题”被误判为没有进展。
7. 上下文扩展保留锚点的归属，保证不同子问题的首个锚点有扩展机会。评估和回答打包均优先保留覆盖不同题的资料，再分配剩余字数；文档元数据、分隔符和正文共同计入原有字符预算。回答提示逐项列出原问题要求，没有足够证据时明确说明。

## 多跳依赖

`depends_on` 只能引用前序子问题，防止环和悬空依赖。首轮只检索无依赖项。上游证据被判定覆盖后，Evaluator 在 `followup_tasks` 中补全下游查询实体，并可提供 `resolved_question`；重排也使用这个已解析的对象和条件。未提供可执行查询的依赖项不会拿含糊模板直接检索。

这不是无限制多跳执行：深度仍受原有轮次、调用数、时间预算约束。上游后续被重新判为不足时，其依赖项不会继续执行。模型没有声明的隐含依赖无法由此调度器自动推断。

## 预算与兼容

- 多子问题的 `agent_tool_calls` 在三路汇合后按实际发出的 Milvus `search/hybrid_search` 请求数累计，包括失败请求、软路由和允许的范围回退。Dense/Sparse 的单次 hybrid_search 计一次。模型调用不计入这一数据库请求计数。
- 调度前预留各操作的最坏请求数，先分配不同子问题的首条召回，再分配其它方式和查询变体；未发生的预留请求不计入累计值。默认 `AGENT_MAX_TOOL_CALLS=6` 保持不变，可能不足以让四题都执行所有召回方式；可按业务成本和延迟提高预算。
- 请求发出前检查总耗时。已经发出的模型/数据库请求仍依赖客户端自身超时，不会被此调度器强制取消。
- `AGENT_SUBQUESTION_TOP_K` 默认 3，`AGENT_RERANK_BATCH_SIZE` 默认 64。多题不再受旧 `RERANK_MAX_TOP_K` / `AGENT_EVIDENCE_POOL_MAX` 的全局截断，结果规模由题数、每题 TopK 及最终字符预算共同限制。
- 用户锁定文档范围时，分组检索不回退全库。普通链路保持原行为。
- 状态的三路分组结果、调用数和错误各用独立键；汇合节点统一读出，避免 LangGraph 并行写同一字段。

## 验证

`tests/test_subquestion_retrieval.py` 使用模拟模型/数据库，覆盖非重叠结果、共享证据、批量重排、低质量结果过滤、失败隔离、按缺失项补检索、多跳依赖、字数预算、请求计数和真实 LangGraph 并行汇合。还需在业务问题集上用相同上下文预算比较各题证据覆盖率、答案完整性、延迟和调用成本，才能判断实际效果提升。
